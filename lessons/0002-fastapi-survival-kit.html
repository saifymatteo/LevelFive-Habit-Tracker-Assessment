Lesson 2 — FastAPI survival kit

⏱ ~20 min Skill: read & modify any endpoint Prereq: Lesson 1

Win of this lesson: you can read any endpoint in this repo and predict exactly what it does — and add a new one that follows the house style. Every endpoint here is built from the same four patterns. Learn the four, and "add/modify functionality" becomes filling in a form.

Dart analogy up front: FastAPI is to Python what shelf + strong codegen would be to Dart — decorators declare routes, type hints declare validation, Depends is dependency injection like Flutter's Provider, but function-argument based.

Pattern 1 — Route decorators

@router.get("/{habit_id}/logs")          # method + path template
def habit_logs(
    habit_id: int,                       # path param, auto-parsed & typed
    limit: int | None = None,            # query param (?limit=5), optional
    db: Session = Depends(get_db),       # Pattern 3
    user: User = Depends(get_current_user),  # Pattern 4
):
    ...
  • The function signature is the request schema. Path params come from the URL template, everything else defaults to query params.
  • The router is mounted with a prefix in main.py: app.include_router(habits.router, prefix="/api/habits"). So @router.get("") = GET /api/habits. Order matters: /search is declared before /{habit_id} so "search" isn't captured as an id.
  • Type hints aren't decoration — habit_id: int means a request to /habits/abc returns a clean 422 validation error before your code runs.

Pattern 2 — Pydantic request bodies

class HabitIn(BaseModel):
    name: str
    emoji: str | None = None
    cadence: str | None = "daily"
    target_per_week: int | None = 7

@router.post("")
def create_habit(payload: HabitIn, ...):

Annotate the parameter with a BaseModel and FastAPI parses + validates the JSON body. Missing required field → automatic 422 with a precise error list. Wrong types → 422. You write zero validation code for the common case, and payload.name is a plain typed attribute.

Pattern 3 — Depends(get_db): the session per request

def get_db():                 # database.py — a "generator dependency"
    db = SessionLocal()
    try:
        yield db              # handler runs with this session
    finally:
        db.close()            # always runs, even if the handler raises
  • One SQLAlchemy Session per request, created before and closed after. This is the repo's unit of work — like Eloquent's connection-per-request in Laravel.
  • All reads/writes go through db: db.query(Habit).filter(...), db.add(obj), db.commit(), db.get(Habit, id) (primary-key lookup), db.delete(obj).
  • Nothing is written until commit(). That's the #1 beginner bug: you db.add() and wonder why the row isn't there.

Pattern 4 — Depends(get_current_user): auth as a chain

def get_current_user(
    authorization: str | None = Header(default=None),
    db: Session = Depends(get_db),       # dependencies can depend on dependencies
) -> User:
    ...  # parses "Bearer ", loads User, or raises 401

user: User = Depends(get_current_user)   # in every protected endpoint

By the time your handler runs, user is a real ORM object or the request already failed with 401. Note what this repo's version does not do: no signature check, no expiry — the token is the user id. You'll justify a proper fix in Lesson 4; for now, know that Bearer 2 logs you in as user2.

Pattern 5 (bonus) — failing & returning

raise HTTPException(status_code=404, detail="Habit not found")  # error path
return {"id": habit.id, "name": habit.name}                      # success: any dict → JSON

HTTPException short-circuits the request into a JSON {"detail": ...} response with the status you chose. Handlers return plain dicts — FastAPI serializes them (dates become ISO strings via the model fields you pick).

Sync vs async, one line These handlers are plain def, so FastAPI runs each in a threadpool — blocking calls (like that time.sleep(0.35) in checkin) tie up a worker thread, not the whole event loop. Don't convert anything to async def on Friday "because async is faster" — with sync SQLAlchemy sessions, plain def is the correct house style.

Lab — feel validation work (5 min)

  1. Open localhost:8000/docs and run POST /api/login via Try it out — it needs no auth. (The authorization field on other endpoints is a decoy: Swagger never sends it — Lesson 1 §4.)
  2. Stash the token in PowerShell: $t = (Invoke-RestMethod -Method Post -Uri http://localhost:8000/api/login -ContentType application/json -Body '{"email":"admin@habit.app","password":"demo123"}').token
  3. POST /api/habits with {}: Invoke-RestMethod -Method Post -Uri http://localhost:8000/api/habits -Headers @{Authorization="Bearer $t"} -ContentType application/json -Body '{}' → read the 422: it names the missing field.
  4. Retry with -Body '{"name":"Assessment prep"}' → 200, and the habit appears in the UI at localhost:5173.
  5. Invoke-RestMethod -Method Delete -Uri http://localhost:8000/api/habits/9999 -Headers @{Authorization="Bearer $t"} → read the 404 detail — that's HTTPException doing its job.
