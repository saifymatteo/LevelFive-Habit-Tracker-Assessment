Lesson 1 — Run it, then trace one request

⏱ ~15 min Skill: run + read the system Mission: assessment-ready

Win of this lesson: the app runs on your machine, you can log in, and you can explain how a login click becomes a database row — the mental model every assessment task will hang off.

1 · Start the stack

You know Docker — this is the one command, plus what's unusual about this compose file:

cd D:/Git/interview-coding-test-main
docker compose up --build
  • db starts first: postgres:16-alpine with user/pass habit/habit, db habitdb, data persisted in the named volume pgdata. A healthcheck (pg_isready) must pass before anything depends on it.
  • backend builds the Python image, installs requirements.txt, and runs uvicorn on port 8000. depends_on: condition: service_healthy is what sequences it after db.
  • frontend is a two-stage build: node:20 runs npm run build, then nginx:alpine serves the static dist/ on port 5173→80 and proxies /api/ to backend:8000.
Heads-up (planted quirk) The login form comes pre-filled with demo@habit.app — that user does not exist. Real seeded accounts (password demo123 for all): admin@habit.app, user1@habit.app, user2@habit.app. user1 has the most data — use it.

3 · Trace one request: login

Follow this path in the actual files — it's the backbone of the app:

  1. frontend/src/components/Login.jsx — form submit calls api("/login", { method: "POST", body: { email, password } }).
  2. frontend/src/api.js — thin fetch wrapper; prefixes /api, JSON-encodes the body, throws on non-2xx using the backend's detail message.
  3. backend/app/routers/auth_routes.py — POST /api/login looks up User by email, compares the password in plaintext, and returns token: str(user.id). Remember that — it comes back in Lesson 4.
  4. Login.jsx stores the token via setToken() (localStorage) and hands the user object up to App.jsx, which flips from <Login/> to <Home/>. There is no router — screens swap by conditional rendering.
  5. Every later call sends Authorization: Bearer <token>. backend/app/deps.py — get_current_user — turns that header back into a User by literally doing int(token).

One more trace, the one you'll modify on Friday: check-in. Dashboard.jsx → api("/habits/3/checkin", { method: "POST" }) → habits.py:checkin → guard: already logged today? → 409. Otherwise insert a HabitLog row with today's date, commit, bump an in-memory STREAK_CACHE, sleep(0.35), return.

4 · The superpower: /docs (and its one trap)

FastAPI generates interactive API docs for free at localhost:8000/docs. What works right now, with zero code changes: browse every endpoint's schema, hit Try it out on POST /api/login (needs no auth), and trigger the automatic 422 validation errors with bad bodies.

The trap: protected endpoints render an authorization input in their Try-it-out form. Fill it with Bearer 1, execute… and you still get 401 “Missing bearer token”. Verified live: Swagger UI renders the field but never sends an Authorization header from a request parameter — that header is reserved for declared security schemes, and this repo (unmodified) declares none. Don't burn assessment minutes on that field.

Two ways to test protected endpoints without touching the repo:

# PowerShell - login, then call with the returned token
$r = Invoke-RestMethod -Method Post -Uri http://localhost:8000/api/login `
  -ContentType application/json -Body '{"email":"admin@habit.app","password":"demo123"}'
Invoke-RestMethod -Uri http://localhost:8000/api/dashboard `
  -Headers @{ Authorization = "Bearer $($r.token)" }

Or, on the /docs tab open devtools console (F12):

fetch("/api/dashboard", { headers: { Authorization: "Bearer 1" } })
  .then(r => r.json()).then(console.log)
Do this now Execute POST /api/login in /docs (works unauthenticated). Then run the PowerShell pair above and compare /api/dashboard vs /api/habits/1/stats — totals + 84-day heatmap + per-habit streaks, vs one habit's streaks and last-7 days.
Assessment gold (say it, don't apply it) “The authorization field in /docs is a decoy — Swagger UI never sends an Authorization header parameter; that header belongs to security schemes. Declaring APIKeyHeader(name="Authorization") in the dependency would make the Authorize button appear and work, with zero runtime change.” That sentence, unprompted, is OpenAPI understanding interviewers rarely hear.
