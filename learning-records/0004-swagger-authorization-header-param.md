# Swagger UI never sends Authorization header params — only declared security schemes get sent

Second lesson correction, proven by driving the real UI: the repo emitted `authorization` as a header *parameter* (OAS 3.1 even renders an input field for it), but Swagger UI silently drops the Authorization header at request time — filling the field with `Bearer 1` and executing returned 401 "Missing bearer token". The only path that works: declare a security scheme. `APIKeyHeader(name="Authorization", auto_error=False)` in deps.py changed the OpenAPI spec only (runtime identical — same 401 paths, same parsing), after which Authorize → `Bearer 1` → `GET /api/habits` returned 200 with data. Both behaviours verified live in the browser, before and after.

**Implications:** the user's diagnosis ("Swagger UI can't do header authorization directly") was correct and is now durable knowledge about the OpenAPI/Swagger boundary. The before/after `deps.py` diff is committed (e7bab01) and doubles as a ready-made interview story. Also established this session: backend runs locally via Run.ps1 (uvicorn --reload; the user's manual `uvicorn` start lacked --reload and masked the change), and the repo now has a clean baseline commit with teaching files gitignored.
